# How to run CVTI — operator app + detection engine

Snapshot: 2026-07-26. Everything is on `main`. This is the practical "how do I
run it" guide. For the science/roadmap status see `plan.md`; for the demo script
see `docs/SUNDAY_DEMO.md`.

## The two moving parts

CVTI is **two processes**, on purpose:

| Process | What it is | Needs |
|---|---|---|
| **The app** (`cvti.app.shell`) | Operator UI — cameras, live wall, alerts, rules, zones, system. A Qt window hosting a web UI. | PyQt6 + WebEngine + OpenCV |
| **The engine** (`cvti.serving.pipeline`) | Detection: batched YOLO + pose/concealment + VideoMAE + the Gemma VLM gate → writes alerts to `events.db`. | torch, ultralytics, transformers, **Ollama + gemma3:4b** |

They talk through **`events.db`**: the engine writes it, the app reads it. Run
both pointed at the **same `--db` / `--output-dir`**.

The app can **launch the engine itself** (the "Start monitoring" button), but for
demos it's often cleaner to run the engine in its own terminal so you can see the
detection log.

## Prerequisites (once)

```bash
cd /path/to/cv-threat-intelligence
source .venv/bin/activate                 # Python 3.9 venv

# UI deps
pip install PyQt6 PyQt6-WebEngine opencv-python-headless

# Local VLM gate
brew install ollama                       # if not installed
ollama serve &                            # leave running
ollama pull gemma3:4b                      # ~3.3 GB, once
```

Video clips live under `CamNuvem Robbery Dataset/…` and `data/test_clips/`
(gitignored — they're on the dev machines, not in the repo).

## Run it — live (engine + app)

Two terminals. **Terminal 1 = Ollama**, **Terminal 2 = engine**, then launch the app.

```bash
# 1) Ollama (own terminal, leave it)
ollama serve

# 2) The engine — pick a site config (see below). Writes to runs/live/
python -m cvti.serving.pipeline \
  --site-config configs/site_demo_live.json \
  --gate-provider ollama --gate-model gemma3:4b \
  --notify console \
  --output-dir runs/live --target-fps 4 --imgsz 512 \
  --seconds 100000 --gate-drain 60

# 3) The app, pointed at the SAME db (new terminal)
python -m cvti.app.shell --site-config configs/site_demo_live.json --db runs/live/events.db
```

First alerts land ~35–45 s after the engine starts (model load + first Gemma
verdict). The engine **loops** the demo clips, so it keeps running.

**Fresh run?** Clear the db first: `rm -rf runs/live && mkdir -p runs/live`.

### Site configs
| Config | Cameras | Use when |
|---|---|---|
| `configs/site_demo_live.json` | **6** (3 threat + 3 quiet) | Full wall. ~2–3 GB RAM for the engine; fine on 18 GB. |
| `configs/site_demo_lite.json` | **3** | Tight machine / quick run. |
| your own | — | Real cameras: add via the app's Cameras tab (scan or paste RTSP). |

## Run it — playback only (any machine, no engine/Ollama)

The **`.dmg`** (or the app with no `--site-config`) plays a bundled recording —
live wall + real recorded alerts, zero setup. Good for showing on a laptop that
doesn't have the ML stack. `docs/SUNDAY_DEMO.md` covers this.

## The screens

- **Live** — camera feeds; a camera lights up red when it's alerting; **click a tile to zoom**.
- **Alerts** — triage queue (Needs review / True / False / All). Open one → it
  **plays as an event clip**; label it (Ack / True / False) → it clears.
- **Rules** — per camera: toggle built-in detectors, write **custom plain-English
  rules**, and **draw zones** (drag a box → loitering rule). Changes apply on the
  next Start monitoring.
- **System** — site name, notification channels, gate health.
- **Cameras** — scan the network / add a camera (RTSP) with Test.

---

## Notifications

Set `notify` in the site config (or System page): comma-separated, e.g.
`console,telegram:<bot-token>:<chat-id>` or `console,whatsapp`.

- **Telegram** sends the alert **with the evidence photos**. Get a bot token from
  @BotFather and your chat id from @userinfobot.
- **WhatsApp** (Twilio) reads creds from env vars (`TWILIO_ACCOUNT_SID`,
  `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_FROM`, `WHATSAPP_TO`) — never committed.

## RAM (Apple Silicon dev box)

- Gemma is ~3 GB (GPU/unified memory; auto-unloads when idle). Engine models
  ~2–3 GB. App ~1 GB.
- 6 cams + engine + app runs comfortably on 18 GB **with other apps closed**.
- If it swaps/beachballs: close Spotify/Brave, or use `site_demo_lite.json` (3 cams).
- Check headroom: `vm_stat`; watch `sysctl vm.swapusage` (want swap "free").
- Production target is an NVIDIA edge box — models go to VRAM, RAM stops being the constraint.

## Troubleshooting

- **No alerts / gate offline** — is `ollama serve` up? `curl localhost:11434/api/version`.
- **Engine exited** — it auto-restarts from the app (watchdog, 5×). From the CLI,
  re-run the command. Check `runs/live/monitor.log` / `run.log`.
- **Too many false positives** — do NOT enable **weapons** in Rules (brittle on
  low-res CCTV, over-fires). Keep threat cams on **concealment + video-theft**;
  keep quiet cams with **no detectors**. The gate filters, but fewer candidates =
  cleaner. Concealment sensitivity: `SCORE_THRESHOLD` in `cvti/retail/concealment.py`.
- **Nothing fires on a theft cam** — video-theft is **gated behind another signal
  firing**, so concealment must trigger first. Don't over-tighten concealment.
- **Camera offline (RTSP)** — decoders reconnect automatically (TCP transport).
- **App window blank / won't open on another Mac** — unsigned build →
  `xattr -dr com.apple.quarantine "/path/CVTI Console.app"`, then right-click → Open.

## Stop everything

```bash
pkill -f "cvti.app.shell"; pkill -f "cvti.serving.pipeline"; pkill -f ollama
```

## Package the desktop app

```bash
python packaging/build.py --clean --dmg      # -> dist/CVTI-Console.dmg (macOS)
```
CI builds macOS/Windows/Linux (`.github/workflows/build-app.yml`). Unsigned —
for distribution you need an Apple Developer ID + notarization.
